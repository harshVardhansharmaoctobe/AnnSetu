# Deploying FoodBridge to Netlify with Neon PostgreSQL

FoodBridge is a standard Next.js 15 App Router project (no middleware, server actions or edge runtime).
Netlify detects Next.js and applies its official OpenNext adapter (`@netlify/plugin-nextjs`)
automatically, so no `netlify.toml` and no extra dependency are needed. Nothing here deploys automatically.

## What the code already handles for Netlify

| Topic | How |
|---|---|
| Prisma engine | `binaryTargets = ["native", "rhel-openssl-3.0.x"]`: Netlify builds on Ubuntu but runs functions on AWS Lambda (Amazon Linux) |
| Prisma Client | generated by `postinstall` and again by `npm run build` (`prisma generate && next build`), so a cached `node_modules` is never stale |
| Image uploads | stored in PostgreSQL (`StoredFile`) on serverless hosts – the function filesystem is read-only – and served only to signed-in users |
| Upload size | 4 MB default on serverless (Netlify functions accept 6 MB, and binary bodies grow ~33 % when encoded) |
| Client IP for rate limits | `CLIENT_IP_HEADER=x-nf-client-connection-ip` (set by Netlify, not by clients) |

## 1. Neon (once)

1. Neon console → project **foodbridge** → **Connect** → branch `production`, database `neondb`.
2. Save the two connection strings locally without showing them:
   `powershell -ExecutionPolicy Bypass -File scripts\neon-env.ps1`
   (pooled string with "Connection pooling" ON, then the direct string with it OFF). This writes
   `.env.neon.local`, which is gitignored.
3. Check and preview, then create the schema – `push` refuses any destructive statement:
   ```powershell
   node scripts/neon.mjs check    # connects (pooled + direct), verifies PostGIS, lists tables
   node scripts/neon.mjs diff     # SQL that would run; destructive statements are flagged
   node scripts/neon.mjs push     # prisma db push, only when nothing destructive is planned
   ```
4. Optional demo/admin accounts: see "Admin and demo accounts" in `docs/DEPLOY_VERCEL.md` (use new
   passwords and `SEED_CREDENTIALS_FILE=none`). Never seed production without deciding to.

## 2. Netlify site

**Add new site → Import an existing project → GitHub → `harshVardhansharmaoctobe/FoodBridge`**

| Setting | Value |
|---|---|
| Branch to deploy | `foodbridge-main` |
| Base directory | *(empty – repository root)* |
| Build command | `npm run build` |
| Publish directory | `.next` |
| Functions directory | *(leave empty – the Next.js adapter manages functions)* |

### Environment variables (Site configuration → Environment variables)

Scope every variable to **Builds and Functions** (the default "All scopes" is fine).

| Variable | Value |
|---|---|
| `NODE_VERSION` | `22` |
| `DATABASE_URL` | Neon **pooled** URL (host contains `-pooler`), with `&connect_timeout=15` appended |
| `DIRECT_URL` | Neon **direct** URL (only needed if schema commands ever run on Netlify; harmless otherwise) |
| `NEXTAUTH_URL` | `https://<your-site>.netlify.app` (or custom domain), no trailing slash – **required on Netlify** |
| `NEXTAUTH_SECRET` | new random value (`openssl rand -base64 32`), never the local one |
| `CLIENT_IP_HEADER` | `x-nf-client-connection-ip` |
| `UPLOAD_STORAGE` | `database` (also the automatic default on Netlify; set explicitly for clarity) |
| `MAX_FILE_SIZE_MB` | `4` |
| `SUPPORT_EMAIL` | real contact – identifies the app to OpenStreetMap's geocoder |
| `GEOCODER_COUNTRY` | `in` (optional) |

Do **not** set: `NODE_ENV`, `UPLOAD_DIR`, `TRUSTED_PROXY_HOPS`, `LOCATION_DEBUG`, `LOG_RESET_LINKS`,
`SEED_*`, `POSTGRES_PASSWORD`, `TEST_DATABASE_URL`.

Unlike Vercel, NextAuth cannot discover the site URL on Netlify, so `NEXTAUTH_URL` is required.
Because it is `https://`, NextAuth uses secure (`__Secure-`) session cookies automatically.

## 3. After the first deploy

- `https://<your-site>.netlify.app/api/health` → `{"status":"ok","database":"up"}`
- Sign in as the admin, approve accounts, run the demo (`docs/DEMO_GUIDE.md`).

## Platform notes

- Netlify functions have a 10-second default timeout; FoodBridge requests are short, but the first request
  after Neon's compute has auto-suspended can take a few seconds (`connect_timeout=15` covers it).
- Rate limits and the geocoder cache are in memory per function instance – weaker than on one server.
- Address search uses OpenStreetMap Nominatim from Netlify's shared IPs; if throttled, users can still
  type the address and place the pin.
- Password-reset emails are not sent; admins issue one-time links from the user detail page.
